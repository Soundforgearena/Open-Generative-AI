This audit covers the Next.js web application, Studio workflows, paid-request safeguards, export fetching, deployment configuration, live read-only connections, and the legacy Electron renderer. Repairs are staged on `copilot/final-clean-implementation`; this document does not claim they are deployed to production.

## Repairs included

- **CI and build:** Incorporated the apostrophe lint repair and manual workflow trigger from the stacked branches. Matched CI to Node 22, added browser checks, production dependency auditing, desktop compilation and failure-artifact capture.
- **Studio project isolation:** Remount project-owned state when the project changes. Cancel deferred save timers, clear old load errors and dialogs, and reject quotes that arrive after the selected scene changes.
- **Director client retries:** Forward the actual caller-supplied idempotency key. Retry the original payload rather than the currently edited text; acquire the local action lock before clearing recovery feedback.
- **Director backend:** Introduced a database uniqueness lock and cached responses. Concurrent/repeated requests cannot call the provider again. A key reused for different input receives a conflict. Missing migration, storage outage and ambiguous failures fail closed.
- **Billing feedback:** Removed unsupported assurances that ambiguous failures were free. Return `settlement_pending` instead of asserting a debit succeeded when settlement failed.
- **Older writing assistant:** Prevent animation completion and “Skip animation” from submitting two paid requests. Snapshot input and request identity, and suppress responses after unmount.
- **Exports:** Check destination DNS addresses, pin vetted addresses to the TLS connection, validate every redirect, reject local/private destinations and credential-bearing URLs, and bound request duration.
- **Desktop:** Fixed the unresolved shared models import, enabled TLS verification in the development proxy, upgraded Electron/Vite/build tooling, and blocked executable/local URL schemes and remote in-window navigation.
- **Dependencies:** Patched production Next.js, image-processing and CSS dependencies. Added focused build-tool overrides where patched versions were available.

## Remaining risks and launch gates

- **Deployment gate:** The additive migration must be applied before deploying the updated Director route. Otherwise Director requests deliberately return 503 without calling the paid provider.
- **In-flight request recovery:** A process that dies after claiming a request leaves it `processing`. Do not delete/reset that row merely because it is old. Check the associated reservation/provider outcome and reconcile first; automatic retries could double-spend.
- **Retention:** Completed response cache rows contain creative output. Define and document a retention period before adding cleanup. Deleting a cached key allows it to be used again, so cleanup must preserve duplicate-spend protection.
- **Authentication security:** Supabase's advisor also flagged disabled leaked-password protection. This is an Auth configuration change, not fixed by the SQL migration.
- **Development advisories:** Remaining reports originate from `braces` and `sprintf-js` plus dependent build tools. Their currently published releases still match the advisory ranges. Do not process untrusted build patterns; do not claim a clean full audit or suppress the findings. A broader Tailwind/build-tool migration is separate from these runtime repairs.
- **Live integration evidence:** A non-billable connection check is not an end-to-end transaction test. Use an approved test account, one explicitly capped provider generation, Stripe test checkout and signed webhook delivery, an authenticated storage upload, and a finished-video download before declaring the system fully production verified.
- **Platform scope:** Linux packaging passed. Native local AI hardware, third-party inference installs and signed macOS/Windows distribution were not exercised.

## Recovery and rollback

The migration is additive and the preceding application revision does not reference `director_requests`. If the deployment regresses, restore the preceding Railway revision while retaining the new table and its records; do not drop data or reset idempotency claims during rollback. Preserve maintenance/test-payment settings and investigate pending requests before permitting a new paid attempt.

## Reproduce the checks

```sh
npm ci
npm test
npm run lint
npm run build
npm audit --omit=dev --audit-level=moderate
npm run vite:build
npx playwright install --with-deps chromium
npm run test:e2e
npm run electron:build:linux:dir
```

Use Node 22.12 or newer. `scripts/check-connections.mjs` performs read-only checks from environment configuration; its `--stdin` mode accepts the deployment-variable response without persisting credentials and prints only status/configuration flags. Do not attach secrets, raw environment dumps or full provider responses to tickets.
